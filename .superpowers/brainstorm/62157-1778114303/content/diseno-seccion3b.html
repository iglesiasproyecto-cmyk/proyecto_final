Diseño SaaS — Sección 3b: Estructura de Rutas Multi-Tenant

El id_iglesia va en la URL como tenant scope. Confirmá la estructura antes de continuar.

🗺️ Nueva estructura de rutas

routes.ts — árbol completo
/ → LandingPage (pública)
/login → LoginPage (pública)
/forgot-password → ForgotPasswordPage (pública)
/app → AppLayout (guard: autenticado)
/app → IndexRedirect (→ super_admin: /app/global | otros: /app/:id_iglesia)
/app/global → SuperAdminLayout (guard: solo super_admin)
/app/global → Dashboard global
/app/global/iglesias → CRUD todas las iglesias
/app/global/administradores → Gestión de admin_iglesia
/app/global/usuarios → Todos los usuarios
/app/global/geografia → CRUD geografía
/app/global/catalogos → Tipos evento, etc.
/app/global/notificaciones → Notificaciones propias
/app/global/perfil → Mi perfil
/app/:idIglesia → TenantLayout (guard: tiene acceso a esa iglesia)
/app/:idIglesia → Dashboard del tenant
/app/:idIglesia/sedes → Sedes de la iglesia
/app/:idIglesia/pastores → Pastores de la iglesia
/app/:idIglesia/ministerios → Ministerios
/app/:idIglesia/usuarios → Usuarios del tenant
/app/:idIglesia/miembros → Miembros
/app/:idIglesia/eventos → Eventos
/app/:idIglesia/tareas → Tareas
/app/:idIglesia/aula → Aula de Formación
/app/:idIglesia/aula/curso/:idCurso → Detalle curso
/app/:idIglesia/aula/curso/:idCurso/servidor/:idUsuario → Progreso
/app/:idIglesia/mi-ministerio → Mi ministerio (lider/servidor)
/app/:idIglesia/notificaciones → Notificaciones
/app/:idIglesia/perfil → Mi perfil

🔀 Redirección automática por rol al hacer login

super_admin
→ /app/global
Puede navegar a cualquier /app/:idIglesia/* para ver ese tenant.
admin_iglesia
→ /app/5 (su id_iglesia desde JWT)
Solo puede acceder a /app/5/*. Otro idIglesia → 403.
lider
→ /app/5/mi-ministerio
Scoped a su iglesia. Solo ve rutas de su ministerio dentro del tenant.
servidor
→ /app/5/mi-ministerio
Igual que lider pero con permisos solo lectura en la mayoría de vistas.

🛡️ Guard del TenantLayout

Lógica de acceso en TenantLayout.tsx
// idIglesia viene del parámetro de ruta
const { idIglesia } = useParams()
const { rolActual, iglesiaActual } = useApp()
if (rolActual === 'super_admin') → ✅ siempre pasa
if (iglesiaActual.id === Number(idIglesia)) → ✅ pasa
else → ❌ navigate('/403') o navigate('/app/[su_iglesia]')
// Todos los servicios usan idIglesia del param, no del contexto
// → URL es la fuente de verdad del tenant activo

⚠️ Impacto en servicios y hooks existentes

Todos los servicios deben recibir idIglesia explícitamente:
• useEventos(idIglesia) — filtra por tenant desde la URL
• useTareas(idIglesia) — filtra por tenant
• useMinisterios(idIglesia) — filtra por tenant
• useUsuarios(idIglesia) — filtra por tenant
• Los servicios de super_admin global no pasan idIglesia (ven todo vía RLS bypass)
• RLS en Supabase es la segunda línea de defensa — aunque se manipule el param, la DB filtra igual
